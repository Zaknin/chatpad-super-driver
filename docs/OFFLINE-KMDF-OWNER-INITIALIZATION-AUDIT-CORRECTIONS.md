# Offline KMDF Owner Initialization Audit Corrections

## Purpose and boundary

This record closes the narrow correction pass for the production request-owner
ordinary-initialization checkpoint. It corrects stale wording, tightens the
semantic guard, and replaces only the evidence-retention entries needed to make
the checkpoint auditable without rebuilding.

The correction does not change production source, project linkage, request
owner implementation, lifecycle behavior, INF/signing/package state, or any
driver runtime behavior. It does not authorize dormant orchestration, WDF
object creation, target discovery, request execution, deployment, loading, or
hardware validation.

## Corrections made

- Documentation now distinguishes the historical linkage-only checkpoint from
  the later production owner-embedding and ordinary-initialization checkpoint.
- The production design now describes current source reality separately from
  still-proposed dormant object orchestration.
- The owner-initialization checkpoint now states that the initializer performs
  its own baseline validation and that `EvtDeviceAdd` performs one additional
  explicit pre-object integration-boundary check.
- Binary evidence now treats Debug object references, Release `/GL` inputs,
  context-object COMDATs, linker tlogs, final PE sections, and source checks as
  combined evidence. It no longer treats PE import absence alone as proof,
  because KMDF APIs dispatch through the WDF function table.
- The production owner-initialization guard now records direct and inferred
  checks separately, checks artifact/manifest containment, and reports explicit
  proof limits.
